P19: 3. Kiến trúc hệ thống & Luồng dữ liệu (Architecture & Data Flow)
P20: 3.1. Kiến trúc MVVM (Model-View-ViewModel)
P21: Dự án áp dụng mô hình MVVM chuẩn hóa giúp phân tách rõ ràng vai trò giữa giao diện người dùng và logic xử lý dữ liệu:
P24: 1. View (Activity / Fragment)
P25: Vai trò: Chịu trách nhiệm hiển thị giao diện và nhận tương tác từ người dùng.
P26: Cơ chế: Đăng ký lắng nghe (observe) sự thay đổi trạng thái từ các LiveData trong ViewModel để cập nhật UI.
P27: Nguyên tắc: Tuyệt đối không trực tiếp xử lý logic nghiệp vụ hay biến đổi dữ liệu.
P28: 2. ViewModel
P29: Vai trò: Nơi tập trung toàn bộ logic nghiệp vụ (business logic) và quản lý trạng thái của UI.
P30: Cơ chế: Sử dụng Transformations.switchMap để tự động kích hoạt các truy vấn từ Repository mỗi khi các biến kích hoạt (trigger variables) thay đổi. Điều này giúp giữ cho UI luôn đồng bộ với dữ liệu mới nhất.
P31: 3. Repository
P32: Vai trò: Kế thừa từ BaseRepository, đóng vai trò là nguồn dữ liệu duy nhất (Single Source of Truth), điều phối và đồng bộ dữ liệu giữa Remote API và Local Database (Room DB).
P33: Quản lý bất đồng bộ: Sử dụng AppExecutors để đẩy các tác vụ nặng (truy vấn mạng, đọc/ghi đĩa) xuống background thread thông qua networkIO và diskIO, sau đó trả kết quả an toàn về UI thread bằng mainThread.
P34: 4. Resource Wrapper (Resource<T>)
P35: Vai trò: Lớp đóng gói dữ liệu trả về từ Repository, giúp View dễ dàng nhận biết và phản hồi theo từng trạng thái của tiến trình.
P36: Các trạng thái cốt lõi:
P37: LOADING: Đang tải dữ liệu (hiển thị progress bar).
P38: SUCCESS: Lấy dữ liệu thành công (kèm theo dữ liệu trả về kiểu T).
P39: ERROR: Xảy ra lỗi (kèm theo thông tin chi tiết về lỗi được phân tích qua lớp ApiError).
P40: ________________________________________________________________________________
P41: 3.2. Luồng xác thực (Authentication Flow)
P43: Tự động làm mới Token (Auto Token Refresh)
P44: Ứng dụng triển khai một dịch vụ chạy ngầm mang tên TokenRefreshService. Dịch vụ này:
1.  Sử dụng ScheduledExecutorService để chạy định kỳ mỗi 5 phút.
2.  Kiểm tra thời gian hết hạn (expiryTime) của JWT token hiện tại được lưu trong SessionManager.
3.  Nếu thời gian còn hiệu lực dưới 10 phút, nó sẽ thực hiện gọi đồng bộ AuthRepository.refreshTokenSync() để gửi yêu cầu làm mới lên endpoint /auth/v1/token?grant_type=refresh_token.
4.  Khi có token mới, SessionManager ghi đè token cũ để đảm bảo các yêu cầu tiếp theo không bị lỗi 401 Unauthorized.
P45: Quy trình Khôi phục mật khẩu (Password Recovery Flow)
P46: 1.Yêu cầu quên mật khẩu:
P47: Người dùng gửi yêu cầu quên mật khẩu trong ForgotPasswordActivity thông qua email.
P48: 2.Gọi API hệ thống:
P49: Hệ thống gọi API recoverPassword(email).
P50: 3.Supabase gửi email xác thực:
P51: Supabase gửi email chứa liên kết đặt lại mật khẩu với Deep Link cấu hình dạng vietsync://reset-password.
P52: 4.Nhận diện Deep Link:
P53: Khi người dùng click vào link trong email, Android OS nhận diện Scheme vietsync và mở ứng dụng, truyền mã Access Token tạm thời nằm trong URL Fragment vào Activity.
P54: 5.Hoàn tất cập nhật mật khẩu:
P55: Người dùng nhập mật khẩu mới và ứng dụng gửi yêu cầu PATCH mật khẩu mới kèm Bearer Token tạm thời đó lên /auth/v1/user để hoàn tất cập nhật.

P57: 4. Chi tiết cấu trúc Cơ sở dữ liệu (Database Schema)
P58: 4.1. Remote Database (Supabase PostgreSQL Schema)
P59: Cơ sở dữ liệu được tổ chức chặt chẽ trên PostgreSQL của Supabase, áp dụng RLS (Row Level Security) để bảo mật tài nguyên:
P60: Bảng users (Lưu thông tin hồ sơ người dùng)
P62: Bảng categories (Lưu danh mục học tập)
P64: Bảng courses (Danh sách khóa học)
P66: Bảng lessons (Bài học trong khóa học)
P68: Bảng enrollments (Đăng ký học tập)
P70: Bảng quizzes & quiz_attempts (Trắc nghiệm bài học)
P71: quizzes: lưu thông tin bài kiểm tra thuộc bài học (lesson_id), điểm sàn vượt qua (passing_score).
P72: quiz_attempts: lưu lịch sử làm bài của học viên (user_id), điểm số đạt được (score), trạng thái đỗ/trượt (passed).
P73: Bảng certificates (Chứng chỉ hoàn thành)
P75: Bảng user_settings (Cấu hình ứng dụng)
P77: Các Database Triggers quan trọng:
P78: on_auth_user_created: Đính kèm vào bảng auth.users của hệ thống Supabase. Khi người dùng mới xác thực thành công, Trigger này tự động chèn thông tin (id, email, full_name, role) sang bảng public users để có thể quản lý và hiển thị công khai.
P79: update_enrolled_count: Đính kèm vào bảng enrollments. Khi có học viên đăng ký mới (INSERT), nó tự động tăng giá trị cột enrolled_count của khóa học tương ứng trong bảng courses.
P80: check_course_completion: Đính kèm vào bảng enrollments. Khi progress_percent được cập nhật lên 100 (UPDATE), trigger tự động chèn một bản ghi cấp chứng nhận mới vào bảng certificates.

P92: 5. API Integration Details
P93: Tất cả các REST API calls đều được định nghĩa thông qua các Interface Retrofit 2 tương ứng với phân vùng của Supabase:
P94: 5.1. Các Interface API chính
P95: AuthApi (Endpoint /auth/v1/)
P96: signUp(SignUpRequest) -> POST signup: Tạo tài khoản mới kèm metadata.
P97: signIn(SignInRequest) -> POST token?grant_type=password: Đăng nhập lấy JWT access_token.
P98: refreshToken(RefreshTokenRequest) -> POST token?grant_type=refresh_token: Refresh access_token.
P99: logout(String bearerToken) -> POST logout: Đăng xuất và vô hiệu hóa token hiện tại.
P100: getUser(String bearerToken) -> GET user: Lấy thông tin user hiện tại từ token.
P101: recoverPassword(RecoverRequest) -> POST recover: Gửi email khôi phục mật khẩu.
P102: updateUser(String bearerToken, UpdateUserRequest) -> PUT user: Cập nhật mật khẩu mới.
P103: UserApi (Endpoint /rest/v1/)
P104: getUser(String idFilter, String select) -> GET users: Lấy thông tin chi tiết hồ sơ người dùng.
P105: updateUser(String idFilter, Map<String, Object> fields, String preferHeader) -> PATCH users: Cập nhật tên, bio hoặc ảnh đại diện.
P106: getUserEnrollments(String idFilter, String select) -> GET enrollments: Danh sách ghi danh của học viên.
P107: getUserCertificates(String idFilter, String select) -> GET certificates: Danh sách chứng chỉ đã cấp.
P108: uploadAvatar(String filename, RequestBody fileBody, String upsertHeader) -> POST /storage/v1/object/avatars/: Tải ảnh đại diện lên Storage bucket.
P109: getUserSettings(String idFilter) -> GET user_settings: Lấy cấu hình ứng dụng của người dùng.
P110: upsertUserSettings(Map<String, Object> body, String preferHeader) -> POST user_settings: Cập nhật hoặc chèn mới cấu hình (Upsert).
P111: CourseApi (Endpoint /rest/v1/)
P112: searchCourses(Map<String, String> queryOptions) -> GET courses: Tìm kiếm khóa học kèm các điều kiện lọc và phân trang.
P113: getCategories(String select) -> GET categories: Lấy danh sách các danh mục học tập.
P114: WishlistApi (Endpoint /rest/v1/)
P115: Quản lý danh sách yêu thích của người dùng thông qua các phương thức GET, POST và DELETE đến bảng wishlists.
P116: 5.2. Cơ chế Xác thực tự động qua Retrofit (AuthInterceptor)
P117: Để giảm thiểu việc chèn thủ công Header vào từng API Call, dự án cài đặt AuthInterceptor vào OkHttpClient:
P118: Mọi API Call đều tự động nhận các Headers bảo mật giúp giao tiếp thành công với PostgreSQL REST API phía sau lớp bảo vệ RLS.

P121: Hệ thống phân quyền được kiểm soát chặt chẽ thông qua lớp RoleManager hỗ trợ 3 vai trò: STUDENT, TEACHER, và ADMIN.
P122: Tùy biến điểm khởi chạy trong MainActivity:
P123: Điều hướng vai trò người dùng tại MainActivity
P124: Khi ứng dụng khởi động thành công từ màn hình Splash, MainActivity kiểm tra vai trò hiện tại của người dùng bằng cách gọi RoleManager.getInstance(this).getCurrentRole().
P125: Nếu vai trò là TEACHER (Giảng viên): Khởi tạo điểm bắt đầu (StartDestination) của đồ thị chuyển trang NavGraph là R.id.fragment_teacher_dashboard (Bảng điều khiển cho giáo viên).

P128: Ứng dụng thiết kế Annotation @RequireRole(RoleManager.Role.TEACHER) dùng để chú thích quyền hạn truy cập của các Fragment (ví dụ áp dụng trực tiếp trên TeacherDashboardFragment.java).

P130: 7. Các điểm sáng kỹ thuật & Trải nghiệm UX (Premium Features)
P131: Ứng dụng được cài đặt các thuật toán và UI Components cao cấp mang lại trải nghiệm chuyên nghiệp:
P132: Cơ chế Debounce tìm kiếm (Instant Search)
P133: Trong SearchViewModel, để ngăn chặn việc gửi hàng chục HTTP request liên tục lên Supabase khi người dùng gõ phím, ứng dụng sử dụng Handler trì hoãn 300ms trước khi chạy query thật. Mọi ký tự nhập thêm trong khoảng thời gian này sẽ hủy (cancel) lịch hẹn cũ và tạo lịch hẹn mới. Khi người dùng nhấn nút Search (Submit), ứng dụng sẽ bỏ qua debounce và gửi request ngay lập tức.
P134: Trải nghiệm Swipe to Dismiss (Vuốt để xóa)
P135: Trong màn hình Danh sách yêu thích (WishlistFragment), người dùng có thể vuốt một mục khóa học sang trái để xóa nó. Logic này được xử lý bằng ItemTouchHelper.SimpleCallback kết hợp tự vẽ nền màu đỏ động (ColorDrawable màu đỏ từ R.color.error) đè lên Canvas (onChildDraw) tạo cảm giác xóa mượt mà, phản hồi tốt.
P136: Skeleton Loading (Giao diện Khung xương tải trang)
P137: Khi danh sách khóa học đang tải, ứng dụng không hiển thị vòng xoay ProgressBar nhàm chán. Thay vào đó, DanhSachKhoaHocFragment tạm thời hiển thị KhungTaiAdapter gồm 6 phần tử giả lập cấu trúc lưới hoặc danh sách của khóa học thật với hiệu ứng mờ nhạt (shimmer) giúp tăng trải nghiệm phản hồi.
P138: Bảo mật lưu trữ
P139: Sử dụng EncryptedSharedPreferences (sử dụng Keystore mã hóa cấp độ phần cứng Android) để lưu trữ tokens xác thực và mật khẩu phiên làm việc, chống việc bị dịch ngược hoặc root máy để đọc trộm token.
P140: Cuộn tự động Banner quảng cáo
P141: ViewPager2 trên trang chủ tự động dịch chuyển Banner sau mỗi 3 giây nhờ Handler và Runnable tự động lặp vòng.

P146: Mặc dù UI trang chủ rất phong phú nhưng toàn bộ dữ liệu danh mục (Categories), các khóa học nổi bật (FeaturedCourses), khóa học đang học tiếp (ContinueLearning) và các khóa học phổ biến (PopularCourses) hiện vẫn được tạo bằng dữ liệu cứng (Mock) trong HomeViewModel.java thay vì gọi API/Repository để lấy dữ liệu thực tế từ Supabase.

P149: Một số Fragment chính mới chỉ có Layout XML rỗng (Logic Java rỗng)
P150: Các màn hình cốt lõi dưới đây hiện tại mới chỉ chứa khung layout giao diện XML, lớp Java chưa được hiện thực hóa logic tương tác, kết nối API hoặc xử lý sự kiện:
P151: LessonDetailFragment.java (Chi tiết bài giảng & phát video học).
P152: MyLearningFragment.java (Danh sách khóa học học viên đang tham gia).
P153: MyCoursesFragment.java (Danh sách khóa học do giảng viên tự quản lý).
P154: CreateCourseFragment.java (Form cho giảng viên điền để tạo khóa học mới).
P155: Annotation @RequireRole chưa được kiểm tra tự động tại Runtime
P156: Mặc dù annotation @RequireRole đã được khai báo trên TeacherDashboardFragment, hiện tại mã nguồn chưa có cơ chế kiểm tra tự động trước khi chuyển trang (ví dụ: Custom NavController hoặc Navigator Interceptor) để chặn truy cập trái phép ở cấp hệ thống. Cơ chế bảo vệ hiện vẫn đang phụ thuộc vào việc điều hướng tĩnh thủ công ở MainActivity.
